# Алимжан — API среды, оценщик и политики агента

Сделай интерфейс расследования и оценку выводов. API здесь — локальный JSON-совместимый контракт для RL. Скриптовой политики достаточно для демо. Любые дополнительные задачи по ИИ и интеграциям остаются у тебя при наличии времени после обязательных проверок. Дедлайн организаторов — **22 ноября 2026, 23:59 по времени Астаны**.

## 19 ноября — контракт и первый сквозной прогон

- [ ] Вместе с Аланом зафиксировать схему эпизода, ID записей и доказательств, значения `type`, канонизацию `affected_ids`, ожидаемые суммы и валюты. Подключить первый эпизод с дублем счёта и ошибкой распределения платежа. Проверить путь от `reset` через запрос документов до `submit`.
- [ ] Реализовать `reset(seed, config) → (observation, info)` и `step(action) → (observation, reward, terminated, truncated, info)`. Первое наблюдение содержит задачу, манифест, краткую политику и бюджет. `reset` изолирует новый эпизод. Версия, seed, конфигурация и одинаковая последовательность действий воспроизводят наблюдения, переходы и награды при повторном прогоне.
- [ ] Реализовать `list_records(table, cursor, limit)`, `get_record(table, id)`, `get_document(doc_id)`, `calculator(expression)` и `submit(findings)`. Ограничить страницу 50 строками, использовать стабильные курсоры, возвращать только запрошенные данные. Калькулятор принимает ограниченную десятичную арифметику. Неизвестное действие или ID даёт короткую ошибку и расходует шаг. Бюджет — 100 шагов с учётом отправки. `submit` завершает эпизод, а исчерпание бюджета без отправки или тайм-аут даёт `truncated=true` и пустой итог.

## 20 ноября — оценка и изоляция

- [ ] Валидировать JSON вывода по §5. Проверять `episode_id` и поля `type`, `affected_ids`, `claimed_amount_minor`, `currency`, `evidence_ids`, `explanation`. Пределы — 30 выводов, 10 ID доказательств и 1 000 символов объяснения на вывод. Неверная структура завершает эпизод с оценкой −1 у оценщика. Повторный `submit` не пересчитывает итог.
- [ ] Сделать детерминированное взаимно однозначное сопоставление. Для TP нужны правильный тип, канонические `affected_ids`, сумма в явно задокументированном допуске, правильная валюта и минимум один полный допустимый набор существующих доказательств. Несопоставленные выводы и дубли — FP, отсутствующие выводы — FN. Опубликовать код нормализации, допусков и разрешения неоднозначных совпадений.
- [ ] Считать P, R и F1 по TP, FP и FN. При нулевом знаменателе P или R равны 0. F1 равна 1 при пустых эталоне и ответе, и 0 при пустом эталоне и непустом ответе. Использовать общую награду `clip(2 * F1 - 1 - 0.002 * inspection_steps, -1, 1)`. Исследовательские шаги дают 0, возврат эпизода равен терминальной награде. В открытом обучении политика получает терминальную награду, в закрытом прогоне закрытые метрики и диагностика остаются у оценщика до конца прогона.
- [ ] Вынести оценщик из процесса агента. Запустить агента без доступа к файлам оценщика и seed, оставив ему узкий интерфейс чтения и отправки ответа. Проверить публичные `observation`, `info`, ошибки, пути и журналы на утечки. У агента есть только действия контракта, без shell, SQL, произвольного доступа к файлам и сети. Oracle запускается только на стороне оценщика.

## 21 ноября — политики, траектории и проверки

Случайный исследователь использует фиксированный seed политики, простая сверка сопоставляет документы и проводки, «пометить всё» отправляет заведомо широкие обвинения в пределах схемы, oracle отправляет выводы из закрытого эталона. Прогнать политики на одинаковом открытом dev-наборе и собрать P, R, F1, возврат, шаги и время.
- [ ] Записать `trajectories.jsonl` с полями `episode_id`, `step`, `action`, `observation`, `reward`, `terminated`, `truncated`. Проверить отсутствие закрытого эталона в наблюдениях. Протестировать точный повтор действий и переходов, изоляцию между `reset` и сохранение результата oracle после перестановки строк и переименования ID в парных эпизодах Алана.
- [ ] Покрыть контракт тестами пагинации, неизвестных ID и действий, неверного ввода, отправки на последнем шаге, тайм-аута и повторной отправки. Проверить, что правильный вывод с доказательствами лучше молчания на ошибочных данных, а на чистых данных молчание лучше ложного обвинения. Покрыть дубли, массовую пометку, угаданные ID, неполные и неподтверждённые доказательства, неверную валюту, пороги округления и небольшой штраф за лишние шаги при одинаковом качестве.
