# Контракт интеграции v1

## Каталог эпизода

Код оценщика получает корень эпизода. Механизм генерации подключается через `AuditEnv(loader=...)`. Функция `loader(seed, config)` возвращает загруженный `Episode`. Стандартный загрузчик читает заранее сгенерированный каталог из `config["episode"]`. Сид и конфигурация генератора остаются на стороне запуска.

```text
episode/
  public/
    manifest.json
    policy.json
    ledger.csv
    invoices.jsonl
    payments.jsonl
    fx.csv
  private/
    truth.json
    provenance.json
```

| Файл | Поля и правила |
|---|---|
| `manifest.json` | `schema_version` (1), `episode_id`, `base_currency`, `period_start`, `period_end`, `timezone`, `record_count` (строки ledger), `document_count` (счета + платежи), `rounding`, `currency_exponents` (карта разрядности валют) |
| `policy.json` | `fx_date_rule`, `period_rule`, `rounding`. Значения — строки. Режим округления совпадает с манифестом |
| `ledger.csv` | `row_id,timestamp,account,debit_minor,credit_minor,currency,entity_id,invoice_id,payment_id` |
| `invoices.jsonl` | `doc_id`, `invoice_id`, `entity_id`, `issued_at`, `due_at`, `currency`, `total_minor`, `line_items` |
| `payments.jsonl` | `doc_id`, `payment_id`, `timestamp`, `currency`, `amount_minor`, `invoice_refs` (массив ID или `null`) |
| `fx.csv` | `date,source_currency,target_currency,rate`. Ключ формируется как `YYYY-MM-DD:EUR:USD` |
| `truth.json` | `{"episode_id":"…","issues":[…]}`. Поля ошибки: `issue_id`, `type`, `affected_ids`, `expected_amount_minor`, `currency`, `evidence_sets` (массив полных допустимых наборов) |
| `provenance.json` | Сид, конфигурация и причинные изменения. Этот файл хранится отдельно для анализа генерации |

Суммы задаются целыми минимальными единицами, курсы — десятичными строками, время — ISO-8601 со смещением. Пустые ссылки в ledger читаются как `null`. В `affected_ids` используется ID проверяемой сущности из таблицы ниже, а в `evidence_ids` — глобально уникальные `doc_id`, `row_id` или составной ключ FX. Каждый набор доказательств должен быть достаточен сам по себе и содержать до 10 ID. Публичная часть предназначена для данных, которые политика вправе прочитать целиком.

| `type` | Канонический объект | Сумма в интеграционных эпизодах |
|---|---|---|
| `duplicate_invoice` | `invoice_id` | сумма избыточного отражения в валюте проводок |
| `payment_allocation` | `payment_id` | остаток между ожидаемым и фактически распределённым в валюте проводок |
| `fx_conversion` | ID документа операции, например `payment_id` для оплаты | правильная конвертированная сумма минус отражённая в целевой валюте |
| `reporting_period` | ID документа операции, например `invoice_id` для счёта | сумма неверно отнесённой проводки в валюте проводок |

По умолчанию допуск составляет **0 минимальных единиц** для всех четырёх типов. Для согласованного тестового запуска можно передать `--tolerances path.json` с картой типов к целым неотрицательным допускам. Сопоставление считает одинаковые нормализованные выводы дублями, затем максимизирует число взаимно однозначных совпадений. Равнозначные варианты обходятся в порядке отправленных выводов и отсортированных `issue_id`. Доказательства сравниваются как множества, описание используется для представления вывода. Для нового набора генератора нужно сверить размерности сумм, знак и допуски с этими правилами.

## Действия и ответы

Внешний доверенный запускатель может вызывать `from audit_sim.environment import AuditEnv`. `reset(seed, config)` возвращает `(observation, info)`, а `step(action)` — `(observation, reward, terminated, truncated, info)`. Приложение передаёт политике только публичные ответы этих методов по JSON-каналу. Прямой Python-объект среды принадлежит доверенному оценщику.

| `action` | Параметры | Результат |
|---|---|---|
| `list_records` | `table`, `cursor` (по умолчанию `null`), `limit` (1–50) | массив записей и `next_cursor` |
| `get_record` | `table`, `id` | одна запись по ключу |
| `get_document` | `doc_id` | один счёт или платёж |
| `calculator` | `expression` | десятичная строка, до 40 значащих цифр |
| `submit` | `findings` (объект с `episode_id` и массивом `findings`) | завершение эпизода |

Допустимые таблицы — `ledger`, `invoices`, `payments`, `fx`. У запросов есть `steps_remaining`, а результат обычно находится под ключом `result`. Ошибки действий приходят под ключом `error` и расходуют шаг. Лимит — 100 действий, включая отправку. Неотправленный прогон оценивается как пустой ответ, с фактическими шагами исследования. При тайм-ауте итог отмечается в `reports.json`, а траектория содержит только реально обработанные действия. Валидная структура неизвестного типа — ложное срабатывание. Структурно неверная отправка завершает эпизод и даёт −1 у оценщика.

### Пример на `demo-mixed`

Запрос к документу:

```json
{"action":"get_document","doc_id":"R-doc-invoice-1"}
```

Документ содержит `invoice_id=R-invoice-1`, сумму `3630` и валюту `USD`. После чтения проводок `R-row-001` и `R-row-003` можно отправить один вывод:

```json
{
  "action": "submit",
  "findings": {
    "episode_id": "demo-mixed",
    "findings": [{
      "type": "duplicate_invoice",
      "affected_ids": ["R-invoice-1"],
      "claimed_amount_minor": 3630,
      "currency": "USD",
      "evidence_ids": ["R-doc-invoice-1", "R-row-001", "R-row-003"],
      "explanation": "Одна и та же сумма отражена дважды по одному счёту."
    }]
  }
}
```

В закрытом режиме политика получает общее подтверждение завершения, терминальный флаг и `reward=0`. После прогона оценщик покажет TP=1 и FN=1, поскольку в этом эпизоде есть ещё ошибка распределения платежа.

## Изоляция и обмен файлами

Оценщик загружает эпизод в доверенном процессе. Политики запускаются в отдельных процессах с пустым рабочим окружением за исключением локали, без унаследованных файловых дескрипторов кроме стандартных потоков. Перед получением задачи worker включает Linux seccomp. Разрешены операции памяти, часы и чтение/запись по уже открытым каналам. Открытие файлов, сокетов и запуск процессов блокируются ядром. При сбое настройки изоляции запуск сообщает об ошибке. Oracle работает на стороне оценщика и его ответы в публичные траектории не записываются.

При интеграции с генератором сохраняйте `public/` и `private/` отдельно. Для внешней изолированной политики направляйте ей JSON-обмен по API. Каталог `private/`, итоговый отчёт и IPC оценщика держите в доверенной части. Контейнер проверен с отключённой сетью.

## Измеренные ограничения

Простая сверка находит полные дубли проводок дебиторской задолженности и неполное распределение в одной валюте. Она опирается на счёт `accounts_receivable` и пропускает случаи, когда опубликованные записи требуют перевода валют или анализа политики признания. Оценщик при этом поддерживает все четыре типа. Малые эпизоды проверяют контракт и расчёт по известным сценариям. Качество на финальном наборе генератора Алана предстоит измерить отдельно.
