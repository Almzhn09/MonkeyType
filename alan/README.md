# Алан — синтетические данные и сборка для сдачи

Сделай генератор компаний, который позволяет проверить каждую внесённую ошибку по видимым записям. Ты также отвечаешь за подготовку эпизодов, контейнера и материалов для сдачи. Дедлайн организаторов — **22 ноября 2026, 23:59 по времени Астаны**.

## 19 ноября — контракт и первый эпизод

- [ ] Вместе с Алимжаном зафиксировать схему эпизода, четыре значения `type`, канонические `affected_ids`, способ вычисления суммы по каждому типу и формат `evidence_ids`. Согласовать стабильный ID для каждой таблицы, включая FX, где можно использовать составной ключ из даты и пары валют. Для первого сквозного прогона передать маленький эпизод с дублем счёта и ошибкой распределения платежа.
- [ ] Сделать детерминированный генератор по `seed` и версионированной конфигурации. Сначала построить согласованные счета, платежи, FX и сбалансированные проводки, затем внести контролируемые изменения и записать их причины. Один эпизод охватывает одну компанию и один отчётный период.
- [ ] Экспортировать открытые `manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv`, `policy.json` по полям из §3 кейса. Время хранить в ISO-8601 со смещением, деньги — в целых минимальных единицах с разрядностью валюты, FX — десятичными строками. Явно указать правила округления и границы периода в часовом поясе компании. Отсутствующие ссылки представить как `null` в JSON и согласованное пустое значение в CSV.
- [ ] Экспортировать отдельно `truth.json` и `provenance.json` для оценщика. Для каждого реального расхождения записать `issue_id`, тип, затронутые ID, ожидаемую сумму, валюту и один или несколько полных допустимых наборов доказательств. Проверить, что доказательства разрешимы из открытых записей и правил. Передавать агенту только открытые записи через API Алимжана.

## 20 ноября — четыре типа и чистые эпизоды

- [ ] Реализовать и отдельно настраивать четыре типа. Для дубля отличать повторное отражение одного счёта от двух законных счетов на одну сумму. Для пропущенного или частичного распределения сверять платёж, его ссылки и фактические проводки. Для FX сравнивать применённую дату или курс с `fx.csv` и `policy.json`. Для ошибки периода сопоставлять дату события и проводки с правилом признания и локальной границей периода.
- [ ] Добавить эпизоды без ошибок и корректные отвлекающие случаи. Включить разбитые платежи, возвраты и законные повторяющиеся суммы. Варьировать имена, ID, порядок, суммы, валюты и часовые пояса без маркеров ошибок в открытых файлах. Ориентир из кейса — 200–2 000 проводок, 20–200 документов и 0–12 ошибок на эпизод.
- [ ] Автоматически проверить исходный баланс, ссылки и суммы, корректность валютных пересчётов и округления, а также расхождение после каждой инъекции. Для чистых эпизодов проверять пустой эталон. Зафиксировать seed и конфигурации тестовых примеров.

## 21 ноября — взаимодействия и воспроизводимость

- [ ] Сделать два сценария взаимодействующих ошибок. Первый — частичный платёж в другой валюте с неверной датой курса около границы периода. Второй — повторное отражение счёта с ошибкой отнесения одной проводки к периоду. Для каждого сценария проверить, что обе причины различимы и для каждого вывода существует полный набор доступных доказательств.
- [ ] Проверить, что одинаковые seed, конфигурация и версия дают одинаковые открытые записи и эталон. Для парных проверок переставить строки и последовательно переименовать ID в записях, ссылках и эталоне. Передать пары Алимжану для проверки неизменной оценки oracle.
- [ ] Подготовить 10 открытых train- и 10 dev-эпизодов с раздельными seed и конфигурациями. Включить чистые случаи, все четыре типа и сочетания. Оставить параметры генератора настраиваемыми, чтобы жюри могло запускать свои конфигурации и seed.

## 22 ноября — упаковка и демо

- [ ] Подготовить контейнер, лицензию и зафиксированные зависимости. Использовать Python 3.11 как ориентир из кейса. Описать сборку и дать одну команду проверки, которая запускает тесты и воспроизводимый прогон без доступа к сети, GPU и платным API. Подключить CLI и тесты Алимжана, проверить работу в контейнере с отключённой сетью. Ориентиры — 2 CPU, 4 ГБ RAM, 1 ГБ на решение и 60 секунд на эпизод.
- [ ] Собрать корневой README, короткую записку о дизайне и комплект сдачи. Включить исходники, схемы, конфигурации, 20 открытых эпизодов, тесты, четыре адаптера и `trajectories.jsonl` Алимжана. Вместе зафиксировать измеренные сбои и ограничения, а также P, R, F1, возврат, шаги и время по политикам.
- [ ] Подготовить показ скриптовой сверки на синтетическом эпизоде. Показать цепочку «запись → доказательство → вывод → оценка» и сравнить с пустым ответом на чистом эпизоде. Убедиться, что файлы оценщика физически недоступны агенту в демонстрируемом запуске.

Источник требований — `genesis.pdf`, §2–3 и §6–10. Даты внутри плана — командные ориентиры.
