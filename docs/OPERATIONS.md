# Прогон, повторная проверка и отчёт

## Ручная сессия

`session` обрабатывает ровно один эпизод. Доверенный запускатель передаёт путь к данным или параметры генератора. Клиент политики работает только со стандартными потоками.

```sh
python3 -m audit_sim session fincheck/fixtures/a08 --output .audit-sim/manual
```

Первая строка вывода содержит `observation` и `info`. Введите одно действие JSON на строку.

```json
{"action":"get_document","doc_id":"DA1K9"}
{"action":"calculator","expression":"2500000 + 2500000"}
{"action":"submit","findings":{"episode_id":"EP-CHK-A08","findings":[]}}
```

Каждый ответ содержит `observation`, `reward`, `terminated`, `truncated` и `info`. В режиме `closed` клиент получает нулевую награду. Итог рассчитывается у оценщика и сохраняется в `reports.json` при использовании `--output`. В режиме `train` клиент получает терминальную награду. Нераспознанный JSON расходует шаг и записывается как пустое действие. Тайм-аут, закрытие ввода и превышение допустимого размера сообщения завершают эпизод с `truncated=true`.

Для нового эпизода используйте `python3 -m audit_sim session --seed 900001`. Для дополнительных параметров генератора укажите `--config ПУТЬ` к JSON-файлу с одним объектом. Для каталогов, расположенных отдельно, укажите `session PUBLIC --private PRIVATE`. Используйте эту схему из доверенного запускающего процесса, который управляет доступом агента к файловой системе.

## Проверка записи

```sh
python3 -m audit_sim replay fincheck/fixtures/a08 .audit-sim/manual/trajectories.jsonl \
  --reports .audit-sim/manual/reports.json
```

Повторный прогон проверяет контрольную сумму начального наблюдения, порядок действий, последующие наблюдения, награду, флаги завершения и итоговый отчёт. Параметр `--reports` нужен для сверки закрытой оценки и восстановления причин завершения, когда тайм-аут или закрытие ввода произошли между действиями. Повторный прогон сравнивает результаты действий и пропускает измерения времени. Для обычных законченных траекторий вместо отчёта можно явно задать `--mode closed` или `--mode train`. Допуски берутся из актуального отчёта или явного `--tolerances`.

В распакованном комплекте проверка обучающих траекторий выглядит так.

```sh
python3 -m audit_sim replay episodes trajectories.jsonl --split train --reports train-reports.json
```

## Диагностика для оценщика

```sh
python3 -m audit_sim score fincheck/fixtures/a08 fincheck/fixtures/a08/control_submission.json \
  --inspection-steps 4 --details
```

Команда использует тот же алгоритм сопоставления и расчёта награды, что и среда. С `--details` видны причины вроде неправильной валюты, неполных доказательств и дубля, а также ID пропущенных ошибок. Этот режим предназначен для доверенного оценщика после прогона.

## Офлайн-отчёт

```sh
python3 -m audit_sim demo --output .audit-sim/demo
python3 -m audit_sim report .audit-sim/manual
```

Откройте созданный `report.html` в браузере. В нём есть сводка по политикам, поиск по ID, выводы, доступные доказательства и последовательность запросов. Скрипт, стили и данные включены в один файл. `train-report.html` в комплекте показывает записанные обучающие прогоны.

## Проверка на новых данных

При пакетном запуске `python3 -m audit_sim run episodes --split dev --jobs 2` два независимых эпизода могут обрабатываться одновременно. Действия сохраняются в том же порядке, что и при последовательном запуске. Время политики в этом отчёте измеряется после загрузки и проверки файлов эпизода.

```sh
python3 -m audit_sim benchmark --batches 5 --seed 6217 --output .audit-sim/benchmark.json
```

В каждой группе 20 новых эпизодов, в том числе пять чистых и минимум пять со связанными ошибками. Данные независимо проверяются вместе с 20 преобразованными копиями. На оригиналах запускаются четыре политики, а на копиях отдельно сравниваются результаты сверки и oracle с оригиналами. Опция `--start-index` позволяет повторить выбранную группу с тем же seed. JSON сохраняется после каждой полностью проверенной группы. Это локальная проверка на синтетике, совместимая с офлайн-запуском.

## Проверка ограничений процесса

В контейнере с отключённой сетью ограничения можно задать на уровне процессов и проверить вывод команды.

```sh
python3 scripts/check.py --offline --cpus 2 --process-memory-mib 384
```

`--offline` проверяет, что в сетевом пространстве имён доступен только loopback. `--cpus` задаёт наследуемый список допустимых CPU, а `--process-memory-mib` ограничивает виртуальное адресное пространство каждого процесса. Это отдельная проверка от общего лимита памяти контейнера.

## Сборка архива

```sh
python3 scripts/check.py --archive .audit-sim/genesis-submission.zip
python3 -m audit_sim verify-package .audit-sim/genesis-submission.zip
```

В ZIP есть SHA-256 и размер каждого файла. Проверка также сверяет состав и число эпизодов. Два архива из одного каталога с одинаковыми байтами получаются одинаковыми. Время исполнения в заново рассчитанных отчётах может отличаться между запусками.
