# Демо Genesis FinTech

Сайт: https://monkeytype-audit.onrender.com — игровой режим, `/dashboard/` — панель проверяющего. Все данные синтетические.

## Подготовка (за 5 минут до показа)

1. Откройте сайт и `/dashboard/`. Бесплатный сервер засыпает без посетителей, и первое открытие занимает около минуты. Поэтому разбудите его заранее и держите обе вкладки открытыми.
2. Запасной вариант без интернета: `python3 -m webapp serve` в корне проекта. Затем откройте http://localhost:7860/ и http://localhost:7860/dashboard/. Сайт и локальная версия показывают одно и то же.
3. В панели проверяющего выберите источник **Demo: A08 control and a clean dev episode**.

## Что показать за две минуты

1. **Задача (15 с).** «Мы построили не ИИ-аудитора, а экзамен для него. Генератор создаёт вымышленные компании с книгой, счетами, платежами и курсами и вносит контролируемые ошибки. Агент через API ищет ошибки и подкрепляет каждую записями, а изолированный оценщик сверяет ответ со скрытым эталоном».
2. **Итог одной строкой (20 с).** Откройте **Benchmark** и выберите источник **Dev split**. Первая строка страницы — готовый вывод: эталонная сверка `reconcile` получает среднюю награду 0,961 при F1 = 1,000 на 10 dev-эпизодах, а атака «пометить всё» `mark_all` получает −1,000. График ниже показывает все четыре политики на оси от −1 до 1 без обрезки. Oracle обведён пунктиром: это контроль оценщика, который читает эталон, а не агент.
3. **От вывода к доказательству (40 с).** Вернитесь к источнику **Demo**. Откройте **Runs → EP-CHK-A08 → reconcile**: 2 вывода, TP 2, FP 0, FN 0, F1 = 1, награда 0,992. Нажмите **Duplicate invoice** и покажите цепочку доказательств:
   - счёт `DA1K9` (INV-77-041, 25 000,00 KZT);
   - две строки дебиторской задолженности `R78CE762` и `R7DD2FD7`, по 25 000,00 KZT каждая. Счёт проведён дважды, переплата 25 000,00 KZT.

   Затем откройте **Payment allocation**: платёж `PB1T3` (PAY-3101, 2 300,00 EUR) и строка `R006E024`, которая ушла на счёт нераспределённых сумм: 407 466,67 KZT. Каждая запись открывается кликом. Вкладка **Activity** показывает пять действий политики по шагам.
4. **Сдержанность вознаграждается (15 с).** Откройте **EP-QRS8HS6811 → reconcile**. Это чистая компания: сверка отправляет пустой ответ и получает 0,984. В таблице **Other Policies** видно, что `mark_all` на той же компании получает −1. Разницу между 1 и 0,984 даёт стоимость восьми запросов к записям.
5. **Попробуйте сами (30 с).** Откройте игровой режим и дайте жюри выбрать компанию. Каждая страница записей стоит шаг из 100, как и для агента, и ответ оценивает тот же оценщик. Самый быстрый вариант — **Talaris Apparel LLC**, чистая компания: сразу нажмите **Submit Findings** с пустым ответом. Результат покажет награду, место среди четырёх базовых политик и эталон.

На вопрос о воспроизводимости: `python3 scripts/check.py` дважды строит данные и сравнивает их побайтно, проверяет 20 парных эпизодов с перестановкой строк и заменой ID и прогоняет 40 dev-запусков. CI запускает эту проверку на Linux, macOS и Windows.

## Шпаргалка: верный вывод в игровом режиме

Компания **Telum Industrial FZ-LLC** (`EP-0CMTEHMK3Z`). Ошибка конвертации валюты в счёте `FILE-TTTDVMC`:

1. Откройте **Invoices**, найдите `FILE-TTTDVMC` и нажмите **Mark as Affected**.
2. Во вкладке **Draft** выберите тип **Wrong currency conversion** и введите сумму `225.54` KZT.
3. Добавьте доказательства `TX-HT49KFD5` и `FX:2026-11-14:EUR:KZT`, затем нажмите **Add Finding** и **Submit Findings**.

Вывод будет засчитан как верный. Вторую ошибку этой компании (`FILE-M41BTWZ`) можно оставить жюри.

## Без браузера

`python3 -m audit_sim demo` печатает те же два сценария в терминале. В контейнере без сети:

```sh
docker run --rm --network none --cpus=2 --memory=4g genesis-audit python -m audit_sim demo
```

## Описание для формы сдачи

**MonkeyType — офлайн-симулятор финансового аудита для Genesis FinTech.** Генератор создаёт согласованную книгу и добавляет четыре настраиваемых типа расхождений, в том числе две комбинации ошибок. Агент через API исследует открытые записи и указывает доказательства. Изолированный оценщик проверяет выводы по типу, ID, сумме, валюте и полному набору доказательств. В архиве находятся исходники, контейнер, 10 train- и 10 dev-эпизодов, 20 вариантов для проверки воспроизводимости, тесты, четыре политики и траектории. Запуск работает на CPU без сети, на Linux, macOS и Windows. Панель проверяющего показывает, как каждый вывод опирается на записи, а игровой режим позволяет человеку пройти тот же экзамен в браузере: https://monkeytype-audit.onrender.com
